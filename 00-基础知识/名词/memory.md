## 结论先行

**Memory** 让 Agent 在多步、多轮、甚至跨任务中保持一致性。完整架构通常拆成三类：

| 类型 | 存什么 | 生命周期 |
|---|---|---|
| **长期记忆** | 用户偏好、角色设定、跨任务先验 | 跨会话 |
| **短期记忆** | 当前任务上下文、近端对话 | 本任务 / 本会话 |
| **工作记忆** | 已完成步骤、中间结果、勾选进度 | 本任务执行中 |

缺记忆的「Agent」容易每步失忆；只有聊天窗口而无外置结构时，会长程爆窗。

---

## 是什么

数据流（对照图2）：

- **读**：Planner / Thinking 读取记忆，避免重复劳动、遵守偏好  
- **写**：Reflection 或执行成功后写回（步骤完成、摘要、偏好更新）  

记忆可以是：键值、向量检索、文件工件、**图结构**（资产图 / 探索图）等。形式服务于「下次决策能否快速拿到对的事实」。

---

## 三类详解

### 长期记忆

- 例：默认报告语言、常用 Slack 频道、角色人设  
- 风险：写错偏好会污染后续任务 → 需用户可编辑 / 可遗忘  

### 短期记忆

- 例：本轮用户目标原文、近 N 条消息  
- 工程：上下文窗口；触顶则靠 compaction / 摘要（pi 等 harness）  

### 工作记忆

- 例：「步骤 1–2 已完成，摘要路径为 …」  
- 工程：todolist、scratch 文件、checkpointer 状态  

---

## 应用场景

- 多日调研任务续跑  
- 团队级共享先验（注意权限与脱敏）  
- 反射后「记住这次踩坑，下次别重复」  

---

## 效益

| 效益 | 说明 |
|---|---|
| 一致性 | 同一约束贯彻全流程 |
| 成本 | 少重复检索与重复提问 |
| 可续跑 | 中断后从工作记忆恢复 |

## 与本仓挂钩

ARTEX **双图 + 冷 digest**、Aurora **世界模型 / engagement_memory**，都是 Memory 的产品级形态：把关键状态从纯聊天记录升级为可压缩、可查询的结构。选型时优先问「记忆是否外置、是否可审计」，而不是「有没有向量库」这一表层问题。
