## 结论先行

**Reflection** 是对执行结果做**质量与合规检查**，并决定：交付、重试、换策略，或打回 Planner。它把 Agent 从「做完就算」变成「做完还要验」。

图2中 Reflection 连回循环，并写回 Memory——这是闭环的关键铆钉。

---

## 是什么

典型检查项：

| 检查 | 例子（中性） |
|---|---|
| 目标达成 | 纪要是否含对比结论 |
| 约束满足 | 是否发到指定 Slack 频道 |
| 结果可信 | 引用是否来自已检索摘要 |
| 是否继续 | 缺数据则回流再收集 |

输出分支：

1. **通过** → 最终答案 / 任务结果  
2. **不通过** → 回流 Reasoning / 核心循环；严重时触发重规划  
3. **记一笔** → 更新工作记忆（已验证 / 已知缺口）

## 应用场景

- 自动发送前的内容审阅  
- 多源信息冲突时的再检索  
- 与**人在环路**结合：Reflection 标红 → 人工批准

## 效益

| 效益 | 说明 |
|---|---|
| 可靠性 | 减少「一本正经地错」 |
| 可运营 | 失败原因可分类统计 |
| 可门禁 | 与确定性规则、审批档位衔接 |

## 与本仓挂钩

产品化 Reflection ≠ 再提示一句「请仔细思考」。本仓强调：**gate / decide / 双向论证 / 不可逆审批** 等机制，把反思做成可强制、可审计的控制流（见竞品 VulnHunter、Aurora）。
