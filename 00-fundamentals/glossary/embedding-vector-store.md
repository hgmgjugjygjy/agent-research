# Embedding / Vector Store（嵌入与向量库）

> 常作为 [RAG](rag.md) 底层；也可服务相似工单、相似代码片段等。

---

## 定义

- **Embedding**：把文本（或代码）映射为稠密向量，使「语义相近」在向量空间中距离更近。  
- **Vector Store**：存储向量并支持近邻检索（ANN）的库或服务；常附带过滤元数据。

---

## 解决什么

- 关键词搜不到的「意思相近」查询  
- RAG 召回、去重、相似案例推荐

---

## 怎么用

1. 选择与语种/代码匹配的 embedding 模型；**索引与查询必须同一模型**  
2. 写入：chunk → embed → upsert（含文档 id、租户、时间）  
3. 查询：embed(query) → top-k →（可选）rerank  
4. 删除/更新文档时同步索引，避免幽灵片段

---

## 常见坑

- 混用不同 embedding 模型导致距离无意义  
- 只向量、无元数据过滤 → 串权限  
- 把向量库当业务数据库（缺事务与强一致时踩坑）

---

## 技术实现原理

> 向量库的索引、距离度量、产品对比等细节以 [vector-database.md](vector-database.md) 为主，本篇聚焦 Embedding 本身。

**Embedding 如何产生**：编码器模型（Transformer）把文本编码为 token 向量，再经池化（mean pooling 或 [CLS]）得到一个 d 维向量（常见数百到数千维），训练目标是对比学习——相似文本对拉近、不相关拉远。

**使用要点**：查询与文档用同一模型（部分模型要求加 `query:` / `passage:` 前缀）；归一化后 cosine 等价于内积；换模型必须全量重建索引。

```python
v = model.encode(["如何重置密码"], normalize_embeddings=True)[0]   # shape (d,)
```

**为什么**：把「语义相似」转化为「几何距离」，才能用近邻搜索在百万级数据里毫秒级找到相关内容。
